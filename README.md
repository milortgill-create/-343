# Sandbox FPS — тестовый полигон физики (Unity URP, Android)

Первая стадия проекта: **закрытый тестовый полигон** для отладки физики и
взаимодействий от первого лица. Деревень, зомби и сюжета здесь сознательно нет —
этот этап существует, чтобы проверить, что предметы падают, летят, бьются и
**не проваливаются сквозь пол**, а манекены и игрок честно кувыркаются рэгдоллом.

Сборка целевая: **Android APK**, полностью офлайн, альбомная (landscape)
ориентация, оптимизация под **Samsung Galaxy A53** (Exynos 1280, Mali-G68).

## Что уже есть на полигоне

### Карта
- Замкнутая арена 26 × 20 × 7 м: бетонный пол (**плита толщиной 1 м**), четыре
  стены, потолок, плинтусы у стен, аварийная разметка и сетка на полу.
- Освещение: направленное «солнце» + 4 потолочных светильника + трёхцветный
  ambient + reflection probe 64 px (один просчёт при старте).
- Геометрия для тестов: платформа 1.3 м, пандус, два стеллажа, тумба.
- Предметы (у всех Rigidbody + гравитация + коллайдер + физический материал):
  **7 ящиков** (дерево, 12 кг), **6 бочек** (металл, 19/22 кг), **9 кирпичей**
  (2.6 кг), **4 доски** (5.8 кг), **10 бутылок** (стекло, 0.42 кг, бьются на
  осколки), **смартфон** (0.19 кг) — стартует в руке игрока.
- **2 манекена-болванки** («Манекен A», «Манекен B»): 15 костей рэгдолла,
  стоят за счёт приводов суставов, реагируют на удары, от сильного удара
  обмякают, отлетают и кувыркаются, через ~9 с сами «восстают».

### Игрок и управление
- Вид от первого лица; **руки персонажа видны внизу экрана** (пустые, без оружия).
- Слева — плавающий **джойстик** движения, справа — зона свайпа камеры,
  справа же кнопки: **ДЕЙСТВИЕ**, ПРЫЖОК, БЕГ, ТЕЛЕФОН, ВЫПУСТИТЬ, РЕСПАВН,
  СТРЕСС-ТЕСТ. По центру — прицел (кольцо + точка), он увеличивается на цели
  и окрашивается, когда цель можно ударить.
- Слева сверху — панель статистики: FPS, профиль качества, предмет в руках,
  подсказка действия, здоровье, состояние манекенов, число тел, статус
  стресс-теста и счётчик «провалов сквозь пол» (в норме всегда 0).
- На ПК: WASD/стрелки + мышь, ЛКМ/E — действие, Space — прыжок, Q — выпустить,
  F — телефон, R — респаун, T — стресс-тест, Shift — бег.

### Физика и взаимодействия (главный фокус этапа)
- **Взять**: навести прицел на предмет, нажать «Действие» — предмет прилипает
  к руке (SphereCast радиусом 0.14 м,reach 2.6 м).
- **Бросить**: с предметом в руках нажать «Действие» — реалистичная баллистика
  (базовая скорость 11 м/с, потолок 18 м/с + добавка от скорости руки).
- **Ударить**: прицел на манекене + «Действие» (кулаком) или удар предметом в
  руках (×1.9 и множитель от массы предмета). Кулак — 150 Н·с, тяжёлый предмет —
  до 969 Н·с: манекен отлетает.
- **Рэгдолл** у манекенов и у игрока: сильный удар/урон → тело обмякает, летит,
  кувыркается. Камера игрока при падении привязывается к грудной кости —
  «кувыркается вместе с телом».
- **Живая камера**: покачивание при ходьбе (0.055 м @ 8.5 Гц), приседание при
  приземлении, тряска от урона с затуханием.
- **Смартфон**: модель телефона в руке; кнопка «ТЕЛЕФОН» берёт его, «Действие»
  бросает — падает и звенит по-настоящему.

### Гарантии против «проваливания сквозь пол»
1. Пол — **плита 1.0 м**, а не тонкая плоскость: путь тела за один физический
   шаг (0.02 c) при максимальной скорости броска — 0.36 м, при свободном
   падении с потолка — 0.23 м, то есть в ~3–4 раза меньше толщины плиты.
2. **Continuous collision detection**: `ContinuousSpeculative` в руках,
   `ContinuousDynamic` в полёте и на телефоне, `ContinuousSpeculative` на
   костях рэгдолла.
3. Решатель 6 + 1 итераций, `maxDepenetrationVelocity = 8`, пониженный порог
   сна, `contactOffset 0.015` — стабильные штабели и кирпичные пирамидки.
4. **Аварийный ограничитель скорости** `SandboxConfig.MaxSafeSpeed = 40 м/с`
   (порог пробоя плиты — 50 м/с): раз в 0.5 с любое разогнанное тело
   принудительно тормозится.
5. **Авто-возврат**: если предмет всё же оказался ниже `KillY = −2 м` или за
   периметром + 8 м — возвращается на точку спавна, счётчик виден в HUD.
6. **Рантайм-проверки в самой игре**: `SandboxSelfTest.Run()` стартует через
   0.8 с после запуска и печатает `РЕЗУЛЬТАТ: PASS/FAIL` в лог; кнопка
   «СТРЕСС-ТЕСТ» 14 секунд пинает случайные предметы и сверяет нижнюю точку
   коллайдеров с уровнем пола.

Численное обоснование всего выше — в отчёте
[`Tools/reports/physics_report.md`](Tools/reports/physics_report.md)
(генерируется `python3 Tools/physics_check.py`, графики прилагаются).

## Требования

- **Unity 2022.3.22f1** (LTS) + модуль **Android Build Support** (OpenJDK, SDK,
  NDK ставятся галочками в Unity Hub).
- Для локальной сборки APK: любой ПК с Unity; для CI-сборки — только секреты
  GitHub (см. ниже).
- Python 3.9+ — только для инструментов проверки (`Tools/`), в игре не нужен.

## Локальный запуск и сборка

1. Открыть папку репозитория в Unity Hub → проект сам создаст `Library/`,
   примени настройки (`ProjectConfigurator`: bundle id `com.milortgill.sandboxfps`,
   landscape, IL2CPP + ARM64, minSdk 24, GLES3+Vulkan, Linear) и создаст URP-ассеты
   (`Assets/_Game/Rendering/URP-Sandbox.asset` + renderer) при первом открытии.
2. Меню **Tools → Sandbox**:
   - `1. Настроить проект (слои, теги, Android)`;
   - `2. Создать/пересоздать URP-ассеты`;
   - `3. Построить полигон в Editor (превью)`;
   - `4. Прогнать самотест физики`;
   - `5. Собрать Android APK` (путь берётся из переменной окружения `BUILD_PATH`
     или аргумента `-buildPath`, по умолчанию `Build/Android`);
   - `6. Собрать Android AAB`;
   - `7. Полный сброс полигона`.
3. Сцена игры одна: `Assets/_Game/Scenes/Sandbox.unity` (уже в Build Settings).

Всё содержимое мира (предметы, манекены, свет, HUD, руки, рэгдоллы) строится
**кодом при старте** из процедурных текстур и примитивов — в репозитории нет
бинарных ассетов, поэтому клон весит килобайты и открывается за секунды.

## Сборка APK через GitHub Actions

Репозиторий содержит workflow **`.github/workflows/android-apk.yml`**:
префлайт-проверка секретов → кэш `Library/` → `game-ci/unity-builder@v4`
(Android, IL2CPP/ARM64) → артефакты `Sandbox-Android` (APK/AAB) и лог Unity →
публикация в Release с постоянным тегом **`apk-latest`** и версионным
`apk-v0.1.<номер сборки>`.

Чтобы сборка пошла, нужно один раз добавить секреты в
**Settings → Secrets and variables → Actions** (достаточно первых двух):

- **`UNITY_EMAIL`** и **`UNITY_PASSWORD`** — почта и пароль аккаунта Unity:
  game-ci активирует бесплатную личную лицензию прямо внутри сборки;
- **`UNITY_LICENSE`** (опционально) — содержимое файла `Unity_lic.ulf`, если
  хочется без пароля: Unity Hub → Preferences → Licenses → Add →
  *Get a free personal license*, затем взять файл
  `C:\ProgramData\Unity\Unity_lic.ulf` (Windows),
  `/Library/Application Support/Unity/Unity_lic.ulf` (macOS) или
  `~/.local/share/unity3d/Unity/Unity_lic.ulf` (Linux).

Пока секретов нет, прогон сборки останавливается на джобе-префлайте и печатает
эту же инструкцию в лог и в шаг «Инструкция, если секретов нет».
Актуальная документация game-ci: <https://game.ci/docs/github/activation>.

После этого любой push в ветку запускает сборку; готовый файл лежит в артефактах
прогона и в Release `apk-latest`.

**Прямая ссылка на свежий APK (постоянная, работает после первой успешной сборки):**
<https://github.com/milortgill-create/-343/releases/download/apk-latest/Sandbox-FPS.apk>

Страница релиза со всеми версиями: <https://github.com/milortgill-create/-343/releases/tag/apk-latest>

Workflow **`checks.yml`** на каждый push/PR прогоняет проверки без лицензии:
целостность метаданных и GUID, валидность сцены/manifest/ProjectSettings,
баланс скобок и опечатки в C# (`Tools/validate_project.py --strict`) и
численную проверку физики (`Tools/physics_check.py`); отчёт с графиками
прикрепляется к прогону.

    GameBootstrap.cs            точка входа: строит мир, игрока, HUD, камеры
    Core/                       утилиты, физматериалы

    Input/                      джойстик и свайпы (legacy Input, офлайн)

## Ограничения этапа

- Это **полигон**, а не игра: нет деревень, зомби, сюжета, сохранения прогресса.
- Графика процедурная и намеренно простая — цель этапа проверить физику и UX
  управления, а не красоту.
- Оружия в руках ещё нет: руки пустые (по заданию этапа).
- APK в этой песочнице собрать нельзя (нет Unity Editor и сети до Unity):
  сборка выполняется в GitHub Actions по инструкции выше.
